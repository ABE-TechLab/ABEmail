# FORGE Principles

1. **Understand before building.** Establish enough context before implementation.
2. **Reason before defaulting.** Choose product, architecture, design, and technology deliberately.
3. **Build the right thing.** Challenge scope, assumptions, duplication, and unnecessary complexity.
4. **Prefer root-cause fixes.** Do not hide structural problems behind patches.
5. **Use the right layer.** Put guidance in instructions, knowledge in modules, and objective checks in tooling.
6. **Keep context living.** Record meaningful product, technical, design, security, and operational decisions.
7. **Protect the guardrails.** Project context can evolve, but core security and quality rules must not be weakened to bypass work.
8. **Verify reality.** A successful edit or build is not proof of a good product. Test the behavior and experience that matter.
9. **Be proportional.** Apply deeper analysis and controls when risk or complexity justifies them.
10. **Optimize for outcomes.** Quality means solving the user's real problem sustainably, not maximizing features or code volume.
